LUMINIX
This webpage is a conceptual demonstration to help understand the Luminix system's purpose.

Redefining the Embedded Engine

A pure C database system blending relational ACID integrity with zero-copy JSON NoSQL capabilities, designed for the extreme edge.

The Problem & The Solution

The Problem

Modern applications require both structured queries (SQL) and unstructured flexibility (JSON). However, traditional massive-scale databases:

  • Demand massive memory footprints (JVMs, background runtimes).
  • Suffer latency penalties when serializing/deserializing deeply nested JSON.
  • Are too bloated to run on resource-constrained IoT edge devices.
  • Force developers to choose between an RDBMS or a Document Store.

The Luminix Solution

We built a monolithic kernel in raw C99 that fuses the two paradigms without the bloat:

  • ACID Core: Slotted-page memory management with a robust Write-Ahead Log ensuring zero data corruption.
  • Zero-Copy JSON: A custom lexer that tokenizes JSON natively on disk, allowing direct access without memory hydration.
  • Minimal Footprint: Runs on less than 16MB of RAM. Zero dependencies. Compiles to a single executable (`luminix.exe`).

Core Architecture

Slotted-Page Storage

Data is stored in customizable 8KB - 64KB pages using a slotted-page architecture. This prevents memory fragmentation and allows for O(1) tuple lookups via in-page directory offsets.

ACID Transaction Manager

We implement the ARIES recovery algorithm. Every transaction appends intentions to a Write-Ahead Log (WAL), ensuring full Atomicity, Consistency, Isolation, and Durability.

High-Speed Indexing

Features dynamic workload-adapted indexes. B-Trees for range queries and sorting, Hash Maps for O(1) exact-match lookups, and Skip Lists for rapid in-memory concurrency.

Zero-Copy JSON Subsystem

JSON payloads are never converted into fat memory trees. A custom lexer tokenizes strings natively, enabling querying of nested data (e.g., `user.profile.age`) on the fly.

Advanced Security

Data at Rest Encryption

The storage engine supports transparent page-level AES-256-GCM encryption. Data is only decrypted inside the volatile memory pool, ensuring that stolen physical hardware remains unreadable.

Role-Based Access Control

Security is enforced at the query parsing layer. Luminix provides granular RBAC allowing privileges to be granted at the database, table, or even specific column level.

Why Pure C?

Zero Hidden Abstractions

Unlike languages with Garbage Collectors (Java, Go) or heavy runtimes, C provides absolute deterministic control over memory layouts. Every byte of the Buffer Pool is meticulously accounted for, preventing unpredictable latency spikes caused by GC pauses.

Pointer Arithmetic

By leveraging direct pointer arithmetic and `mmap`, Luminix can traverse B-Tree nodes and parse nested JSON tokens in a zero-copy fashion. We don't allocate intermediary objects—we read directly from the memory-mapped file.

Extreme Portability

C99 allows Luminix to be compiled for incredibly obscure architectures. From massive x86_64 servers to highly constrained ARM Cortex-M IoT devices running bare-metal, if it has a C compiler, it can run Luminix.

Predictable Performance

In high-frequency trading and edge computing, average latency isn't enough—tail latency (P99) is critical. C allows us to guarantee microsecond latencies by eliminating background tasks and runtime overhead.
